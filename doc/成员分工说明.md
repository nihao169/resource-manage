# 成员分工说明

适用项目：文件管理系统；架构：Vue + Nginx + FastAPI + PostgreSQL + MinIO。

以 A、B、C 代称三位成员，团队可替换为真实姓名。本文只划分职责，不表示业务已经实现。

## 1. 分工原则与当前基础

| 成员 | 主模块 | 核心责任 |
| --- | --- | --- |
| A | 前端 / Nginx | 页面、交互、API 调用、前端构建、HTTPS 与代理 |
| B | PostgreSQL / 元数据后端 | 表结构、认证权限、元数据、搜索、事务、数据库操作及后端集成 |
| C | MinIO / 文件传输后端 / 部署 | 对象存储、上传续传、校验、下载、补偿及部署环境维护 |

B 和 C 同时负责对应的 FastAPI 路由和 Service，并非只负责部署数据库。后端只有一个 FastAPI 服务，不为两人分别创建服务。

当前工程已具备前后端目录、HTTPS、健康检查、22 张业务表迁移、三个私有 Bucket 和账号隔离。业务接口尚未注册，业务页面为待实现入口。因此 B 应在现有表结构上实现业务，不重新设计一套数据库；C 应按现有对象规则实现传输，不仅创建 Bucket。

项目根目录为 `D:\kaixuexiangmu\ziyuanbu`。下文路径均相对此根目录。“现有”表示骨架文件已存在；“拟新增”表示建议开发时创建，本次分工文档不创建这些代码文件。

## 4. C：MinIO / 文件传输后端 / 部署负责人

### 负责功能

- 维护对象键、私有 Bucket、业务账号策略与 MinIO 适配器。
- 实现创建上传、二进制分片、续传查询、取消和完成上传的 FastAPI 调用层。
- 小文件流式存储、大文件 multipart、服务端大小与 SHA-256 校验。
- 正式对象不可覆盖、存储去重、临时对象清理、失败补偿。
- 鉴权后的文件及历史版本流式下载、Range、响应头与连接释放。
- 物理清理中的对象操作与重试编排；调用 B 的引用检查与清理检查点方法。
- 为复制、历史恢复和备份提供必要对象操作；共享提交仍走同一数据库方法。
- 维护 Compose 网络、端口、卷、secret 挂载、初始化和启动脚本；保持工程可启动。
- 汇总模块测试与部署结果；备份命令编排由 C 主责，数据库操作由 B 提供，前端代理由 A 提供。

C 不直接定义或提交第二套数据库事务，不绕过 B 的权限和配额检查；不向前端提供存储密钥或对象路径，不提供秒传或全局哈希查询，不把 ETag 当作 SHA-256。

## 7. 对接顺序与团队交付

1. 三人先阅读既有架构与三份契约；B/C 确认数据库共享方法、锁与事务边界，A 确认公开请求/响应。
2. C 保持工程可启动；B 优先交付认证权限和共享数据库方法；A 可按契约并行开发页面，C 可并行实现适配器和传输流程。并行开发不等于跳过依赖，存储业务联调仍需 B 的方法可用。
3. 先跑通登录 → 空间/目录 → 上传及续传 → 提交版本 → 列表/搜索/下载，再跑版本恢复、软删除/恢复和受控物理清理；每段接口必须真实实现后再注册。
4. 各负责人提交模块测试、接口说明和待完成事项；C 汇总运行 `scripts/test.ps1` 与冒烟检查，B/C 补充业务并发及失败场景，A 验收页面状态。

四天 MVP 与延期功能仍以原契约标记为准，不因为分工覆盖完整模块就要求四天实现全部扩展。基础骨架测试不能代替上传、版本、权限、配额和清理的业务验收。
