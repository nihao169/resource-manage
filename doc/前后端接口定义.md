# 前后端接口定义

版本：1.0；状态：开发契约，尚未实现端点；部署：Vue与FastAPI经Nginx同源。

关联文档：[架构](文件管理系统技术架构文档.md)、[表结构](PostgreSQL表结构设计.md)、[对象规则](MinIO对象规则.md)。接口、表结构和对象状态必须同时更新，不能由各模块自行改变字段含义。

## 1. 范围、负责人和通用约定

### 1.1 功能标记与权限

- **M**：四天MVP必须实现；**E**：完整设计、后续实现，未实现的接口返回404，不提供绕过检查的临时实现。
- **公开**：无登录；**登录**：有效账号和会话；**空间读**：active空间成员或管理员；**文件读**：空间读加文件可见；**文件管**：文件读加所有者或管理员；**管理员**：有效admin。
- 用户对所有资源操作均需空间权限，即便曾经是文件所有者。管理员可检查disabled空间；用户不能访问disabled空间。管理员也不能绕过冻结账号检查。
- 新建文件、发布/恢复版本、复制和新建目录要求空间active，即便操作者是管理员；disabled空间可由管理员检查、修改空间状态、维护保留策略或受控清理。
- 列表、搜索和不可见资源编号不泄露存在性：返回404或空列表；可见但非本人管理操作返回403。
- deleted文件仅管理员或仍有空间权限的所有者可查详情和恢复，下载必须active。清理detach之后不存在文件，只能查看清理历史。
- PostgreSQL负责人（C）实现认证、管理、元数据及查询API；MinIO负责人（D）实现上传、下载和版本流程；前端（A）对接全部公共DTO；Nginx/集成（B）负责代理、部署、验收。

### 1.2 基础协议

| 项 | 约定 |
| --- | --- |
| 前缀 | 所有业务接口 `/api`；Nginx保留此前缀，FastAPI路由同样包含它 |
| 编码 | UTF-8；JSON为application/json；分片为application/octet-stream |
| ID | 小写标准UUID，JSON字符串；数据库id在DTO中命名为file_id/version_id等明确字段 |
| 时间 | UTC RFC3339，如2026-09-17T08:00:00Z；date字段为YYYY-MM-DD |
| 大小 | 字节整数，最大不超过JavaScript安全整数9007199254740991 |
| 哈希 | SHA-256小写64位十六进制，不接受ETag替代 |
| 数值元数据 | number类型用十进制字符串，最多14位整数、6位小数，不允许指数形式 |
| 分页 | page默认1，page_size默认50、最大200；页码超出返回空items，保留total |
| 名称 | NFC归一化并去首尾空白；文件名最长255，禁止路径分隔符和控制字符 |
| 空值 | 可空字段使用null；数组为空用[]；PATCH未提交字段不修改，显式null仅清空可空字段 |
| 校验 | 请求未知字段或不支持查询参数返回422 VALIDATION_ERROR，不静默忽略 |
| 请求关联 | 服务端生成request_id UUID，响应头X-Request-ID；不直接信任任意外部值 |

成功响应统一：HTTP 200（创建201），没有204空响应。`data`内容见各端点。

```json
{
  "data": {"items": [], "page": 1, "page_size": 50, "total": 0},
  "request_id": "90000000-0000-4000-8000-000000000001"
}
```

失败响应：

```json
{
  "error": {
    "code": "QUOTA_EXCEEDED",
    "message": "空间剩余配额不足",
    "details": {"required_bytes": 1234, "available_bytes": 1000}
  },
  "request_id": "90000000-0000-4000-8000-000000000002"
}
```

`details`是白名单字段，禁止返回SQL、堆栈、Bucket、object_key、密码、完整令牌或MinIO错误原文。下载成功为二进制，下载开始前的错误仍为上述JSON。

### 1.3 Cookie、CSRF和会话

生产HTTPS使用：

| Cookie | 值 | 属性 |
| --- | --- | --- |
| __Host-fm_access | access JWT，含sub/sid/token_version/exp | Secure、HttpOnly、SameSite=Lax、Path=/，15分钟 |
| __Host-fm_refresh | 256-bit随机刷新令牌 | Secure、HttpOnly、SameSite=Strict、Path=/，登录起7天绝对到期 |
| __Host-fm_csrf | 绑定sid、带到期和随机值的HMAC签名CSRF令牌；登录前绑定预认证随机nonce | Secure、非HttpOnly、SameSite=Strict、Path=/，最多7天 |

- 先GET `/api/auth/csrf`取得CSRF并设置Cookie；所有POST/PUT/PATCH/DELETE（包括登录、刷新、退出和分片）必须发送`X-CSRF-Token`，与Cookie常量时间比较并验证签名和到期。
- 所有修改请求的Origin必须等于配置的公开HTTPS源；缺失或不匹配拒绝403，不接受任意通配CORS。CSRF签名使用独立secret。
- 前端请求使用credentials=same-origin；不能把访问/刷新令牌存localStorage或URL，登录响应不返回令牌文本。
- 登录和刷新轮换CSRF；前端读取新响应或Cookie后更新请求头。CSRF令牌可以返回JSON，访问与刷新令牌只能通过Set-Cookie。
- CSRF签名在登录后绑定当前sid，登录/刷新时校验旧绑定后轮换；GET csrf可通过有效access或refresh确定sid，否则签发预认证令牌。该响应Cache-Control为no-store。
- access采用HS256白名单算法、至少256-bit独立密钥、固定issuer=file-manager和audience=file-manager-web；不得接受令牌自选算法。确认令牌与CSRF使用不同签名密钥。
- 每个受保护请求校验JWT签名/过期，并查询users和sid对应refresh_sessions，检查账号active、token_version匹配、session未撤销且未到期。
- refresh在会话行锁下轮换token_hash/token_id，但不延长原7天期限；前端使用single-flight避免多个刷新请求竞争。旧刷新令牌返回401，不自动把合法并发请求当攻击冻结账号。
- logout撤销当前sid，清除三Cookie；force-logout、改密、冻结/停用递增token_version并撤销会话，已有访问令牌立即被数据库检查拒绝。
- “立即失效”指撤销事务提交后新请求会被拒绝；已经开始的下载流不保证中途强制终止，最终上传提交仍重新检查授权。
- must_change_password用户只允许me、改密、logout；其他业务返回403 PASSWORD_CHANGE_REQUIRED。
- 本地开发使用HTTPS开发入口保持Cookie语义，不把不带Secure的测试配置部署到生产。

### 1.4 幂等、重试和状态码

- 表中标记 **K** 的修改端点要求`Idempotency-Key`：8–128位可打印ASCII，建议UUID。按actor+key全局唯一；同key不同方法、路径或请求摘要返回409 IDEMPOTENCY_CONFLICT。
- 摘要对method、规范化路径和规范化JSON（键排序、应用默认值后）计算SHA-256；不得包含Cookie/CSRF。密码只进入短暂摘要计算，不落明文日志或响应快照。
- 业务更新、成功审计、幂等完成结果同事务提交。重放仍校验当前权限，返回原HTTP状态及data、当前request_id，头`Idempotency-Replayed: true`。
- 请求锁被占用返回409 OPERATION_IN_PROGRESS及Retry-After: 2。存储故障、配额暂不足、超时不完成幂等记录，释放锁后同key可重试；终态校验错误可以缓存脱敏错误。
- 保证至少7天；被业务记录引用的请求长期保留。完成上传额外以upload_id永久绑定结果，永远不因换key重复建版本。
- 分片 **P** 以upload_id+part_no+真实size/checksum幂等，不用K；Cookie认证端点 **A** 使用自身会话语义，不支持K；GET为 **R**。
- 目标被彻底清理后普通幂等结果返回410 RESULT_GONE；清理/备份历史快照允许返回。权限撤销后不返回旧成功结果。
- 前端网络错误或502/503/504采用同key退避重试；分片先查询状态，完成上传先查询committed状态。不重试修改时生成新key。

| HTTP | code | 意义 |
| --- | --- | --- |
| 400 | INVALID_RANGE、INVALID_REQUEST | 格式错误或无效范围语法 |
| 401 | UNAUTHENTICATED、INVALID_CREDENTIALS、SESSION_EXPIRED | 未登录、令牌失效；登录错误不透露账号是否存在 |
| 403 | FORBIDDEN、ACCOUNT_FROZEN、CSRF_INVALID、ORIGIN_FORBIDDEN、PASSWORD_CHANGE_REQUIRED | 权限或安全校验拒绝 |
| 404 | FILE_NOT_FOUND、VERSION_NOT_FOUND、UPLOAD_NOT_FOUND、NOT_FOUND | 不存在或不可见 |
| 409 | OPERATION_IN_PROGRESS、IDEMPOTENCY_CONFLICT、PART_MISMATCH、PARTS_INCOMPLETE、VERSION_CONFLICT | 并发、重传或版本条件冲突 |
| 409 | RETENTION_BLOCKED、LEGAL_HOLD、DIRECTORY_NOT_EMPTY、NAME_CONFLICT、CROSS_SPACE_OPERATION_NOT_SUPPORTED | 业务状态不允许 |
| 409 | UPLOAD_ALREADY_COMMITTED、UPLOAD_CANCELLED、CONFIRMATION_USED、LAST_ADMIN_REQUIRED、CONSISTENCY_ERROR | 终态、安全或引用一致性冲突 |
| 410 | UPLOAD_EXPIRED、RESULT_GONE、CONFIRMATION_EXPIRED | 期限到达或原结果已删除 |
| 413 | FILE_TOO_LARGE | 声明/实际文件或请求体超限 |
| 415 | FILE_TYPE_NOT_ALLOWED | MIME/扩展名策略不允许 |
| 416 | RANGE_NOT_SATISFIABLE | 单段范围无法满足 |
| 422 | VALIDATION_ERROR、HASH_MISMATCH、SIZE_MISMATCH、PART_SIZE_MISMATCH、METADATA_INVALID | 字段或字节校验错误 |
| 422 | UNKNOWN_SETTING、SETTING_OUT_OF_RANGE、INVALID_CONFIRMATION | 配置/确认令牌不合法 |
| 429 | RATE_LIMITED | Nginx入口限流，提供Retry-After |
| 503 | STORAGE_UNAVAILABLE、DATABASE_UNAVAILABLE、MAINTENANCE_MODE | 依赖故障或维护写屏障 |
| 504 | OPERATION_TIMEOUT | 同步操作预算耗尽，可按检查点重试 |
| 500 | INTERNAL_ERROR | 未分类错误，仅返回request_id用于排查 |

以下各端点除列出的业务错误，还适用本节认证、CSRF、校验、并发、依赖错误；不在每行重复列举。

| CreateBatch | total_count:1..100 |

## 3. 端点定义

表中“输入”包括query或JSON，未写body表示无body；path UUID名称即该段参数。状态默认200；创建标明201。输出指统一data内容，下载除外。

### 3.1 认证与当前用户（C，M）

| 方法/路径 | 权限；幂等 | 输入 | 输出 | 特定错误 |
| --- | --- | --- | --- | --- |
| GET /api/auth/csrf | 公开；R | 无 | {csrf_token,expires_at}并设置CSRF Cookie | RATE_LIMITED |
| POST /api/auth/login | 公开+CSRF；A | LoginInput | 201 AuthResult并设置Cookie | INVALID_CREDENTIALS、RATE_LIMITED |
| POST /api/auth/refresh | refresh Cookie+CSRF；A | 无 | AuthResult并轮换Cookie | SESSION_EXPIRED、UNAUTHENTICATED |
| POST /api/auth/logout | 当前session或refresh Cookie+CSRF；A | 无 | {logged_out:true}，清Cookie；已失效也成功 | CSRF_INVALID |
| GET /api/auth/me | 登录；R | 无 | User | UNAUTHENTICATED |
| POST /api/auth/password | 登录；K | PasswordInput | {password_changed:true,logged_out:true}；撤销所有会话、清Cookie | INVALID_CREDENTIALS、VALIDATION_ERROR |
| GET /api/auth/sessions | 登录；R | page/page_size | `Page<Session>`，仅本人 | 无 |
| DELETE /api/auth/sessions/{session_id} | 登录本人；K | 无 | {session_id,revoked:true}，当前session撤销时清Cookie | NOT_FOUND |

改密或撤销当前会话后，原认证不能用于幂等重放；客户端响应丢失应重新登录，而不是沿用失效会话请求。logout在无有效令牌时也清Cookie，不需返回账号信息。

### 3.2 用户管理（C，E；MVP用受控CLI初始化）

| 方法/路径 | 权限；幂等 | 输入 | 输出 | 特定错误 |
| --- | --- | --- | --- | --- |
| GET /api/admin/users | 管理员；R | page/page_size、q可选最长100、role/status可选 | `Page<User>` | 无 |
| POST /api/admin/users | 管理员；K | username、display_name:1–100、password:12–128、role默认user | 201 User，must_change_password=true | NAME_CONFLICT |
| GET /api/admin/users/{user_id} | 管理员；R | 无 | User | NOT_FOUND |
| PATCH /api/admin/users/{user_id} | 管理员；K | display_name、role、status任选 | User | LAST_ADMIN_REQUIRED |
| POST /api/admin/users/{user_id}/force-logout | 管理员；K | 无 | {user_id,revoked:true} | NOT_FOUND |
| POST /api/admin/users/{user_id}/reset-password | 管理员；K | new_password:12–128 | {user_id,password_reset:true}；must_change_password=true并撤销会话 | NOT_FOUND |

无注册及用户物理删除接口。不得冻结/停用/降权最后一个active管理员；变更序列化检查。账号改密和状态变化均审计，但不写密码或哈希。

### 3.3 空间与成员（C）

| 阶段/方法/路径 | 权限；幂等 | 输入 | 输出 | 特定错误 |
| --- | --- | --- | --- | --- |
| M GET /api/spaces | 登录；R | page/page_size；admin可传status | `Page<Space>`，用户只见active成员空间 | 无 |
| M POST /api/spaces | 管理员；K | CreateSpace | 201 Space | NAME_CONFLICT |
| M GET /api/spaces/{space_id} | 空间读；R | 无 | Space | NOT_FOUND |
| E PATCH /api/spaces/{space_id} | 管理员；K | PatchSpace | Space | QUOTA_EXCEEDED、NAME_CONFLICT |
| M GET /api/spaces/{space_id}/members | 管理员；R | page/page_size、status可选 | `Page<Member>` | NOT_FOUND |

创建时owner始终为操作者；admin代发布不变owner。仅上传创建者可写分片和完成，admin可以检查/取消但不能接管别人的会话。

分片方案来自服务端，不由前端重新计算阈值。服务端流式读取并仅缓冲当前分片验证，最大32 MiB；单文件顺序分片、最多4文件并发。最后一个分片为余数，小文件一个分片，零字节一个空分片。expected_sha256必填，浏览器需增量哈希。

完成请求不接收前端ETag列表，服务端读取已confirmed分片。complete在600秒预算内同步组装校验提交；超过返回OPERATION_TIMEOUT，原会话检查点可重试。校验终态失败需要新建会话，配额/存储临时失败可保留uploaded。取消会话标记failed并清理临时内容，不删除正式文件。

### 3.7 版本与下载（D，M；保留管理E）

| 阶段/方法/路径 | 权限；幂等 | 输入 | 输出 | 特定错误 |
| --- | --- | --- | --- | --- |
| M GET /api/files/{file_id}/versions | 文件读；R | page/page_size，固定version_no降序 | `Page<Version>` | FILE_NOT_FOUND |
| M GET /api/files/{file_id}/versions/{version_id} | 文件读；R | 无 | Version | VERSION_NOT_FOUND |
| M POST /api/files/{file_id}/versions/restore | 文件管、active；K | RestoreVersion | 201 FileCommit | VERSION_NOT_FOUND、VERSION_CONFLICT、QUOTA_EXCEEDED |
| M GET /api/files/{file_id}/versions/{version_id}/download | 文件读、active；R | Range可选；不接受令牌query | 二进制200/206，安全响应头 | VERSION_NOT_FOUND、INVALID_RANGE、RANGE_NOT_SATISFIABLE |
| E PATCH /api/admin/files/{file_id}/versions/{version_id}/retention | 管理员；K | PatchRetention | Version | VERSION_NOT_FOUND、OPERATION_IN_PROGRESS |

**没有POST /versions直接上传的第二套协议**：发布新版本必须POST /uploads指定target_file_id，然后上传分片并complete。并发发布在行锁下分配递增版本号，后提交者成为current；不默认拒绝先创建的上传。历史恢复可通过expected_current_version_id要求乐观校验。

下载响应：

| 响应头 | 规则 |
| --- | --- |
| Content-Type | 版本确认MIME，未知用application/octet-stream |
| Content-Disposition | attachment；filename安全ASCII回退+filename* UTF-8百分号编码 |
| Content-Length | 本次字节数 |
| X-Content-Type-Options | nosniff |
| Cache-Control | private, no-store |
| X-File-SHA256 | 全文件SHA-256，即使Range也保持全文件值 |
| X-File-Version | 十进制version_no |
| Accept-Ranges | bytes |
| Content-Range | 206返回bytes start-end/size；416返回bytes */size |

只接受单段`bytes=start-end`、`bytes=start-`、`bytes=-suffix`，end超出截到文件末尾；start大于等于size或零长度suffix返回416。多段Range返回400 INVALID_RANGE。0字节无Range返回200/Length0，有Range返回416。浏览器可直接同源链接下载，Cookie自动携带；不得为下载把整个大文件读为Blob。下载流已经开始后的中断不能改为JSON错误。

### 3.9 二次确认与清理（C/D，E）

| 方法/路径 | 权限；幂等 | 输入 | 输出 | 特定错误 |
| --- | --- | --- | --- | --- |
| POST /api/admin/confirmations | 管理员；K | ConfirmInput | 201 Confirmation | INVALID_CREDENTIALS、NOT_FOUND |
| POST /api/admin/files/{file_id}/purge | 管理员；K | {confirmation_token:string} | Cleanup；同步完成为200，失败按错误并带attempt_id | RETENTION_BLOCKED、LEGAL_HOLD、INVALID_CONFIRMATION、CONFIRMATION_USED |
| GET /api/admin/cleanup-attempts | 管理员；R | page/page_size、status/file_id可选 | `Page<Cleanup>` | 无 |
| GET /api/admin/cleanup-attempts/{attempt_id} | 管理员；R | 无 | Cleanup | NOT_FOUND |

确认令牌签名包含actor/action/target/jti/exp，并对应数据库记录；可由原行重新生成签名以幂等重放，无需明文存令牌。消费确认与建立attempt同事务。未完成attempt存在时不能新建purge，返回OPERATION_IN_PROGRESS及attempt_id；应对原attempt重新确认并retry。

detach后文件记录不存在，前端显示“逻辑文件已清理，部分存储清理待重试”，不能给出回收站恢复按钮。retry使用历史attempt而不是重新寻找file。保留及冻结检查在detach前再次执行；内容删除和失败检查点见对象规则。

```json
    "uploader":{"id":"10000000-0000-4000-8000-000000000001","username":"alice","display_name":"Alice"},
    "created_at":"2026-09-17T08:02:00Z"
  }
}
```

complete返回200而不是再次201；创建上传本身已为201。重复complete用同upload返回原version，即使已有后续版本，不能把“当前最新版本”当成此次提交结果。

### 4.4 搜索和版本恢复

搜索URL示例：`/api/search?q=项目&space_id=20000000-0000-4000-8000-000000000001&extension=pdf&page=1&page_size=50&sort=relevance`。SearchItem的file与上例同形，match_source=name，score至少100；不返回对象键或正文片段。

恢复历史版本请求：

```json
{
  "source_version_id":"50000000-0000-4000-8000-000000000001",
  "expected_current_version_id":"50000000-0000-4000-8000-000000000002",
  "version_note":"恢复到V1内容"
}
```

返回FileCommit，upload_id=null、version_no为3、restored_from_version_id为V1。不得返回V1作为新的current版本编号。

## 5. 前端状态与Nginx约定

### 5.1 前端

- 状态为准备/排队/上传/等待完成/成功/失败；准备含增量哈希，等待完成含服务端组装和校验。这是上传反馈，不建立文件正文处理状态。
- 上传进度按已确认字节累加，分片请求发送100%不等于版本提交成功；complete成功才显示文件可用。
- 网络中断先查询Upload与confirmed parts；已committed刷新文件列表，不重复创建上传。终态failed/expired明确提示重新选择或创建会话。
- 仅UNAUTHENTICATED/SESSION_EXPIRED的401做一次single-flight refresh并重放原请求；refresh失败转登录。登录或改密的INVALID_CREDENTIALS直接提示凭证错误，不刷新；不把CSRF403当令牌过期。重复401停止重试。
- 403显示权限原因并更新按钮；409显示冲突或短暂重试；413/415/422停止盲目重试；503/504保留幂等键和upload_id。
- 筛选编码URL；“我的上传”使用owner_id，“版本上传者”使用uploader_id；下载用同源链接，不把大文件完整读到前端内存。
- 删除与恢复成功后重新取列表；detach后的清理失败只显示attempt重试，不显示文件恢复。

### 5.2 Nginx

| 项 | 约定 |
| --- | --- |
| 静态资源 | 前端dist构建产物；SPA回退仅用于页面，不用于/api |
| API代理 | `/api/`保留完整路径转发到api:8000；不二次剥离前缀 |
| Cookie | 不删除Set-Cookie、不改写到不安全属性；HTTPS公开源固定 |
| 分片 | client_max_body_size 34m；FastAPI按预期size再限制，JSON body另限64 KiB |
| 缓冲 | 上传分片proxy_request_buffering off；下载proxy_buffering off；HTTP/1.1代理 |
| 超时 | 普通查询60秒；分片300秒；complete/purge/retry读超时660秒；E备份3660秒；API预算必须更小 |
| 限流 | login按IP每分钟10次，burst5；refresh每分钟30次；普通API每秒20次，burst40；分片限制并发而非低速率 |
| 代理信任 | 仅信任Nginx来源的X-Forwarded-For/Proto，服务端不信任直接客户端伪造值 |
| 健康 | live可公开且脱敏；ready仅内网和Nginx允许来源，外网拒绝 |
| 故障 | 413/429尽量输出统一JSON；前端仍兼容代理502/504非JSON响应 |

不启用跨源CORS；如果未来改为不同源，必须重新评审Cookie、CSRF、下载和CORS，而不是直接允许所有Origin。

## 6. 内部协作、验收及追踪

### 6.1 后端内部方法

以[对象规则第8节](MinIO对象规则.md#8-内部方法契约与人员对接)为唯一方法边界定义：C提供权限、上传状态、版本提交与引用事务；D编排存储和补偿；方法通过Service/Repository调用，不创建第二个后端服务。

最终提交方法至少接受actor/session、upload_id或恢复来源、ready对象描述、幂等请求编号及request_id；返回FileCommit。必须在事务内重查权限/配额，不能只接受未经验证的前端owner/object_id。

### 6.2 能力映射

| 架构能力 | 表/内部记录 | API/执行方式 | 主负责人 |
| --- | --- | --- | --- |
| 认证与撤销 | users、refresh_sessions | auth及admin/users | C |
| 空间目录配额 | spaces、space_members、directories | spaces、directories | C |
| 上传续传/版本下载 | uploads、parts、files、versions、objects | uploads、versions/download | D+C |
| 元数据搜索 | files/current_version及关联字段 | files、search | C |
| 删除恢复 | files.deleted字段 | DELETE files、restore、recycle-bin | C+D |
| 标签/自定义字段 | tags/fields/values | tags、metadata-fields、files/metadata | C，E |
| 物理清理 | confirmation、cleanup_attempts/items | confirmations、purge、retry | D+C，E |
| 配置/审计 | settings、audit_events | admin/settings、audit | C |
| 备份/引用核对 | backup_runs和manifest | 受控命令、admin/backups | B+D+C |
| 部署和健康 | 迁移版本与存储探针 | health、components、Nginx | B |

验收必须覆盖：完整登录上传下载；多文件独立失败；分片中断与错误重传；Complete响应丢失；并发版本与配额竞争；管理员代上传；撤销会话/成员；幂等重放越权；Range下载；软删除搜索不可见；保留冻结阻止清理；detach中断和旧对象重试；备份恢复。

**验证状态**：本交付只静态核对路由、JSON及数据映射，没有实际HTTP服务。前端负责人据此Mock，后端实现后由FastAPI生成OpenAPI，并与本文逐项对照；B在集成环境运行契约测试后标记运行验收通过。

## 7. 安全参考

- [OWASP CSRF防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)：采用绑定会话的签名双提交令牌与Origin校验，不只依赖SameSite。
